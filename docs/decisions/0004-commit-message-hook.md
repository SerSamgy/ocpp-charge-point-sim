# 0004. Conventional Commits enforced by a versioned git hook

## Context

The repository is public and the history should be readable and easy to
scan by type of change. Rules that are only written down tend to drift.

## Decision

Use Conventional Commits (`type(scope)!: subject`) with the types feat,
fix, refactor, perf, test, docs, build, ci, chore, style, revert. The
subject is at most 72 characters and has no trailing period.

The rule is checked by `.githooks/commit-msg`, a POSIX sh script without
external dependencies, stored in the repository. Each clone enables it
once with `git config core.hooksPath .githooks`. Messages generated by
git (`Merge `, `Revert "`, `fixup! `, `squash! `) are not checked. The
hook was the first commit, so every commit in the history passed it.

## Consequences

- The hook is versioned and reviewed like code; changes to the rules are
  visible in history.
- It only works where it is enabled and can be bypassed with
  `--no-verify`; a CI check is needed to enforce it for contributions
  (listed in the roadmap).
- No Node.js or Python tooling (commitlint, pre-commit) is required.

> Update: commit messages are now also checked in CI by the `commits`
> job, see `docs/decisions/0006-ci-on-github-actions.md`.
